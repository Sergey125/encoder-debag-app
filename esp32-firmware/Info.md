# ESP32-H2 BLE Rotary Encoder Firmware

Прошивка для платы **ESP32-H2**, превращающая обычный поворотный энкодер
(KY-040 / EC11 или аналогичный, до 600 импульсов на оборот) в BLE-датчик
положения. Позиция крутится по кругу от **0 до 599** и рассылается по
Bluetooth Low Energy в виде текстовых сообщений — можно проверить готовым
BLE-терминалом (например, **nRF Connect**), без написания собственного
клиента.

## Аппаратная часть

| Сигнал | Пин ESP32-H2 |
|--------|--------------|
| CLK    | GPIO3        |
| DT     | GPIO4        |

Кнопка энкодера не используется — обрабатывается только вращение.

Питание и GND энкодера подключаются штатно; пины CLK/DT настроены с
внутренними подтяжками (`INPUT_PULLUP`), внешние резисторы не нужны.

Опционально: адресный RGB-светодиод (WS2812) на **GPIO8** — используется
для визуальной индикации без необходимости в Serial-мониторе.

## Принцип работы

- Квадратурное декодирование выполняется **аппаратным блоком PCNT**
  (Pulse Counter) чипа, а не прерываниями на GPIO — счёт идёт в железе
  независимо от загрузки процессора и BLE-стека. Это даёт устойчивую
  работу на высоких скоростях вращения, включая энкодеры с 600 PPR.
- Позиция циклическая: `0 → 1 → … → 599 → 0` и в обратную сторону.
- Устройство рекламируется в эфир под именем **`encoder`**.
- Сервис и характеристика соответствуют **Nordic UART Service (NUS)** —
  де-факто стандарту передачи данных по BLE, понятному большинству
  готовых BLE-приложений:
  - Service UUID: `6E400001-B5A3-F393-E0A9-E50E24DCCA9E`
  - TX Characteristic UUID: `6E400003-B5A3-F393-E0A9-E50E24DCCA9E`
- Формат сообщений: `ENC:<дельта>\n` — знаковое число шагов, накопленных
  с прошлой отправки (например, `ENC:3` или `ENC:-1`). Абсолютную
  позицию 0–599 клиент должен вычислять сам, накапливая эти дельты.

## Настройки прошивки

Все параметры собраны в начале `.ino`-файла:

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `REQUIRE_ENCRYPTION` | `0` | `1` — требовать PIN **123456** при подписке на нотификации |
| `STEPS_PER_DETENT` | `4` | Сколько сырых квадратурных отсчётов = один "шаг". `4` — для детентных энкодеров (щелчки), `1` — для промышленных датчиков без детентов, где важна каждая единица разрешения |
| `PULSES_PER_REV` | `600` | Диапазон циклического счёта |
| `SEND_INTERVAL_MS` | `10` | Как часто проверяются накопленные шаги и отправляется BLE-нотификация |
| `LED_OFF_DELAY_MS` | `150` | Сколько держать красный светодиод после последнего замеченного вращения |
| `PCNT_HIGH_LIMIT` / `PCNT_LOW_LIMIT` | `1000` / `-1000` | Окно аппаратного счётчика PCNT между переполнениями |
| `PCNT_GLITCH_FILTER_NS` | `1000` | Фильтр дребезга контактов, наносекунды |

## Индикация светодиодом

При старте, после успешного запуска рекламы BLE:

- **3 зелёные вспышки** — реклама запустилась успешно, устройство видно в эфире.
- **5 красных вспышек** — реклама не стартовала (ошибка инициализации BLE-стека).

Во время работы:

- **Красный** — идёт вращение энкодера (гаснет через `LED_OFF_DELAY_MS`
  после остановки).
- Погашен — энкодер в покое.

## Зависимости (библиотеки Arduino)

- `NimBLEDevice` — NimBLE-Arduino, версия **2.x**
- `Adafruit_NeoPixel`

Устанавливаются через **Инструменты → Управление библиотеками**.

## Требования к плате

- Плата в Arduino IDE: **ESP32-H2 Dev Module** (или аналог для вашего
  конкретного модуля).
- Ядро `esp32` (Espressif) версии **3.x** — более старые версии не
  поддерживают ESP32-H2 и не содержат нужный API `driver/pulse_cnt.h`.

## Прошивка и проверка

1. Выберите плату и порт, залейте скетч.
2. Дождитесь 3 зелёных вспышек светодиода — подтверждение, что реклама
   BLE началась.
3. Откройте **nRF Connect** на телефоне, найдите устройство `encoder`,
   подключитесь.
4. В списке сервисов раскройте **Nordic UART Service**, у характеристики
   **TX** включите нотификации (три стрелки вниз).
5. Покрутите энкодер — в поле Value должны появляться строки вида
   `ENC:1`, `ENC:-2` и т. д.

## Известные ограничения

- Кнопка энкодера физически не обрабатывается прошивкой — вращение и
  только вращение.
- При потере части BLE-нотификаций (плохое соединение, помехи)
  накопленная на стороне клиента позиция может разойтись с реальным
  положением энкодера. Прошивка не хранит абсолютную позицию между
  переподключениями и не пытается её восстанавливать.
- Требование к плате именно **ESP32-H2** — код использует новый
  ESP-IDF-драйвер PCNT (`driver/pulse_cnt.h`), недоступный на классическом
  ESP32 в том же виде.
